How to read the numbers

Measured data. With the "Measured" source the curves are real runs from SemiAnalysis InferenceX (public database dump, last 120 days, no speculative decoding). Each point keeps its framework, precision, GPU count and topology, with a link to the run. InferenceX covers fewer models and only three workloads without prefix cache, and every GB300 run is a disaggregated multi-node Dynamo recipe, so part of the gap with B300 may come from recipe tuning. RTX PRO 6000 has only a handful of Qwen3.5 runs.

Simulated data. With the "Simulated" source the results are not measured and use synthetic traffic: every request in a scenario has the same input and output length, and cache reuse is a fixed share of the prompt rather than real multi-turn or agentic sessions. Use them to compare systems, not to predict production numbers.

Source. Each point is a configuration found by aiconfigurator cli default from the AISimulate package (TensorRT-LLM backend, vLLM for DeepSeek V4 Flash; SILICON perf database) with a 72-GPU budget: GB300 NVL72 (one NVLink rack), B300 HGX NVL8 (9 nodes of 8 over InfiniBand), RTX PRO 6000 server (9 nodes of 8, PCIe). AISimulate is experimental and NVIDIA positions it for evaluation, not for production capacity planning.

Dynamo on / off. On: the best of aggregated and disaggregated serving, with the selected cache hit (assumed to be achieved by the KV-aware router). Off: aggregated serving only and no prefix reuse across replicas (round-robin routing). This is a modelling assumption: the Dynamo router is not simulated request by request in this version.

Traffic. GPUs needed are estimated by linearly scaling the per-GPU throughput of the best point that meets the SLA. Above 72 GPUs this is an extrapolation.

Benchmarks. Published accuracy scores, mostly vendor-reported.
